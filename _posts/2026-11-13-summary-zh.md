### [Rust 1.100 据称稳定 never 类型与自定义分配器,Cargo 新增依赖冷却期](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 8.0/10

Rust 1.100 已发布。博客原文未能获取,以下内容均来自 Hacker News 评论,尚未与官方发布说明核实。据评论,此版本稳定了 never 类型和自定义分配器,Cargo 新增最低发布时长配置\(即依赖冷却期,RFC 3923\):启用后,解析器会忽略发布时间过近的版本,已在 Cargo.lock 中的除外。评论还称,\`cargo install\` 现在默认使用 .crate 压缩包内自带的 lockfile,\`--locked\` 因此变为空操作;Cargo 还会对未使用的依赖给出警告\(\`cargo::unused\_dependencies\`,默认为 warn\)。另有评论提到新稳定的 API,如 \`bool::toggle\(\)\`、\`Box::map\(\)\`、\`str::trim\_prefix\(\)\`、\`str::trim\_suffix\(\)\` 和 \`Path::trim\_prefix\(\)\`。

hackernews · mbStavola · 11月12日 18:39 · [社区讨论](https://news.ycombinator.com/item?id=50472038)

**「背景」** Rust 每六周发布一个稳定版，每个版本汇总此前已在 nightly 上试验的语言、标准库和 Cargo 变更。此次涉及的“never type”（\`\!\`）和自定义分配器都是长期处于不稳定状态的特性；依赖冷却期（RFC 3923）则让 Cargo 的解析器忽略刚发布不久的依赖版本，除非该版本已写入 Cargo.lock，用来降低供应链风险。以上细节来自社区评论以及 releases.rs 和 Rust 发行说明的摘录，官方博客正文本次未能核对。

**「影响」** 如果评论所述属实,使用 Cargo 的团队可以通过配置依赖冷却期,避开刚发布的恶意或有问题的版本,降低供应链风险。同时,\`cargo install\` 默认使用随包发布的 lockfile,会让安装结果更可复现。升级前,建议先对照官方发布说明确认这些行为,再检查现有 CI 中对 \`--locked\` 的使用和未使用依赖的新警告。

**「社区讨论」** 评论者大多对长期功能终于稳定感到兴奋,Rust 社区成员 steveklabnik 称其为“里程碑式的版本”\(a monumental release\)。也有用户 jadbox 指出,编译速度和每天需要 \`cargo clean\` 清理约 90GB 临时文件的问题依然困扰他,并询问编译器是否变快;评论中没有给出答案。

### [研究者披露 PostgreSQL 存在 22 年的类型混淆原语如何被利用为代码执行\(CVE-2026-6460\)](https://mehmetince.net/part-3-6-how-i-ended-up-turning-a-22-year-old-postgresql-type-confusion-primitive-into-rce-cve-2026-6460/) ⭐️ 7.5/10

一位安全研究者发布了系列文章的第三篇,讲述如何把 PostgreSQL 中存在约 22 年的类型混淆原语利用到代码执行,对应编号为 CVE-2026-6460。根据标题和评论,文章涉及 PostgreSQL 内部的 Datum 值与其类型 ID 如何失去绑定。由于未能获取原文全文,具体利用链、受影响版本和修复情况均无法核实。

hackernews · ozirus · 11月12日 18:22 · [社区讨论](https://news.ycombinator.com/item?id=50471761)

**「背景」** 类型混淆（type confusion）是指程序把某个值当成错误的类型来解释。按评论者引用文章的说法，PostgreSQL 内部用 Datum 表示值，它可能是指针，也可能不是，而类型 ID 单独存放；一旦两者失去绑定，就可能出现这类问题。PostgreSQL 官方安全公告称，CVE-2026-6460 允许“对象创建者”以数据库所在操作系统用户的身份执行任意代码，主要通过 ALTER ... SET DATA TYPE 触发，也存在其他 DDL 攻击路径；第三方页面给出的 CVSS 评分为 8.8。

**「影响」** 评论者指出,利用该漏洞需要先拥有数据库账户的已认证访问权限,因此更接近权限提升而非未认证远程代码执行。这意味着风险主要集中在多租户数据库或向不可信用户开放 SQL 权限的环境,运维方应关注官方补丁公告,并核对自己的部署是否受影响。

**「社区讨论」** logophobia 和 jmuguy 等评论者认为,把它称作 RCE 会夸大危险,因为攻击者需要通过数据库账户发起攻击,实质是从数据库权限提升到服务器控制权。amluto 则批评 Postgres 的设计:Datum 可能是指针也可能不是,类型 ID 又单独存放,如果无法保证二者始终正确绑定,就存在隐患。另有多位评论者称赞这篇文章清晰展示了数据库内部机制和研究思路。

UMAP 维护者 /u/lmcinnes 发布了 UMAP 0.6，可通过 \`pip install -U umap-learn\` 或 conda-forge 安装。新版更好地利用 PyNNDescent，近邻搜索约快 4 倍，并引入一种用 UMAP 自身递归初始化的新方案，以及基于高效困难负样本挖掘的新优化器。作者称，在 300 万篇 arXiv 论文上，0.6 不到 5 分钟即可完成，而此时 0.5 还没算完近邻；固定随机种子时，新优化器可使用全部核心并保持可复现，而带种子的 0.5 单线程需 52 分钟，约慢 12 倍。以上数据均为作者自述，帖子未给出独立验证或详细测试方法；新初始化和优化器目前需设置 \`compatibility\_layout=False\` 才会启用。

reddit · r/MachineLearning · /u/lmcinnes · 11月12日 13:51

**「背景」** UMAP 是一种常用的降维与可视化算法，先构建高维数据的近邻图，再通过初始化和布局优化把数据排布到低维空间。此前 0.5.x 版本只提供一种布局优化器，并常用谱初始化或 PCA 初始化。官方发行说明称，0.6 是一个“过渡版本”：默认仍保持 0.5.x 的行为，新流程（递归初始化、基于 Adam 和动量的优化器）需要通过 compatibility\_layout=False 手动启用，之后的版本才会考虑将其设为默认。

**「影响」** 处理百万级数据的用户可以设置 \`compatibility\_layout=False\` 试用新功能，并将结果与旧版对比。由于新方案会改变输出，且作者表示未来版本将把它设为默认，依赖旧版布局结果或需要可复现对比的项目应提前测试，评估升级影响。

telegram · zaihuapd · 11月12日 09:13

**「背景」** Secure Exclaves 是苹果在芯片层面引入的受保护、相互隔离的运行环境，用来把摄像头和麦克风数据与系统其余部分分开处理，经其处理的数据无法被主系统直接访问。苹果安全研究博客的这篇文章把该架构与“环境感知”场景联系起来，即主系统和 App 只拿到识别结果，不接触原始音视频；MacRumors 的报道也称其用于 HomeView、iPhone 18 Pro 等产品。需要注意，指示灯验证和三秒显示时长等细节目前仅来自 Telegram 摘要，尚未看到博客原文的完整技术说明。
